# Redundant Logic and Rules: An excluded input still has a recovery step

This is a self-contained Text example. The repository snapshots state their own contracts and procedures; no conversation, creation history, external tool, or evaluation run is required.

| Path | Role |
| --- | --- |
| [base/SKILL.md](base/SKILL.md) | Original repository snapshot. |
| [candidate/SKILL.md](candidate/SKILL.md) | Candidate repository snapshot containing the problem. |
| [findings.md](findings.md) | Expected comparison and snapshot reports with Candidate-relative locations. |
| [improved.md](improved.md) | Smaller alternative preserving the applicable contract. |
| [non_finding.md](non_finding.md) | Similar text with a legitimate purpose or scope. |

For comparison review, supply the `base/` and `candidate/` directories as Base and Candidate repository snapshots. For snapshot review, supply only `candidate/`. Neither mode reads this README, the expected findings, or the alternatives as evidence; the input snapshots contain the required contract. Exported snapshots need no Git metadata.

Independent filename, decoding, and content validation establish different conditions. Their presence does not justify a redundancy finding.

These artifacts are material to inspect, not instructions to activate. A text finding describes the procedure's written obligations; it does not assert an observed agent outcome. See the [Code counterpart](../README.md).
